VIRTUAL ROADS - UPGRADES AND FIXES (version 2.0, branch "laptop", 2026-11-25)
====================================================================================

Issue IDs refer to ../draft.txt (my review: V1-V11, test findings T-V1..T-V10) and to
suggested_improvements_virtual_roads.docx (B01-B40).


1. HOW TO RUN (one unbroken command)
------------------------------------------------------------------------------------
    python run_virtual_roads.py                       # example with defaults
    python run_virtual_roads.py --config other.toml   # your own settings file
    python run_virtual_roads.py --set surface.max_slope_deg=12 --set paths.run_name=s12
    python run_virtual_roads.py --print-config        # see every setting
    python -m pytest -q                               # 11 tests, ~5 s

Environment: Python 3.12 with GDAL, geopandas, rasterio, scikit-image (requirements.txt /
environment.yml). Tested in the conda env "mucp" (GDAL 3.11, geopandas 1.1, shapely 2.1,
rasterio 1.5, scikit-image 0.26).

Output of a run: results/<run_name>/
    virtual_roads.gpkg          layers: paths, origins, paths_wgs84, origins_wgs84
    virtual_roads_summary.csv   one row per origin (status, length_m, cost, climb, slopes ...)
    bea_start_vertices.gpkg     origin points (Point, EPSG:4326, fid2, length) for the BEA model
    bea_end_vertices.gpkg       road end points (same fid2) for the BEA model
    run.log, run_manifest.json  log; settings, library versions, input SHA-256, timings
    work/                       projected DEM, slope, cost and road rasters

4. ALGORITHM IMPROVEMENTS
------------------------------------------------------------------------------------
a) Projected, isotropic analysis grid. The DEM is warped to the CRS of the BSU template
   (Albers equal area, metres) at surface.cell_size_m (30 m). Slope is Horn's method in
   degrees. North-south and east-west moves now cost the same per metre.

b) Cost model "distance_slope" (default):  cost per metre = 1 + slope_weight * slope / max_slope.
   The original used slope alone, so flat ground was free and routes could wander
   (legacy routes up to 10.2 km; new max 5.4 km, median 16% shorter for the same origins).
   The original behaviour is still available: --set surface.cost_function=slope_only.

c) Multi-source routing. One MCP_Geometric run per tile, seeded from ALL road cells, gives
   the cheapest cost from every cell to the network; each origin is then a traceback. The
   original ran one MCP per origin and rasterised the road layer per origin.
   Example: routing 222 origins went from ~49 s to ~1 s.

d) Adaptive window buffer (replaces the fixed 0.01 degree window). If no road is reachable
   or a path touches the window edge, the buffer is doubled (up to
   routing.max_tile_buffer_m) and the origin re-routed. This removes edge effects instead
   of hoping the buffer is big enough. Paths still limited at the maximum are flagged
   (edge_limited = true).

e) Richer attributes per route: length_m, cost, climb_m, descent_m, max_slope_deg,
   mean_slope_deg, snapped_m, buffer_m, road end coordinates.

f) Direct hand-over to the BEA model: bea_start_vertices.gpkg / bea_end_vertices.gpkg with
   Point geometries (the original MultiPoint vertices break current GDAL in BEA, see
   bea_feasibility_upgrades.txt).


5. SETTINGS (all in config.toml; defaults = original hard-coded values where one existed)
------------------------------------------------------------------------------------
[paths]   dem, obstacles_dir, roads, grid_template, roi, output_dir, run_name
[surface] analysis_crs ("" = template CRS), cell_size_m = 30, dem_resampling = bilinear,
          dem_fill_max_distance_cells = 0, max_slope_deg = 15 (original), cost_function =
          distance_slope (original: slope_only), slope_weight = 1, restrict_to_roi = true
          (original), roi_buffer_m = 0, obstacle_all_touched = true, road_all_touched = true,
          road_filter = "" (e.g. "FEAT_TYPE != 'Street'")
[points]  origin_spacing_m = 1000 (original), snap_origin_radius_m = 100
[routing] tile_size_m = 20000, tile_buffer_m = 1000 (original ~0.01 deg),
          max_tile_buffer_m = 16000, fully_connected = true (original)
[output]  gpkg_name, write_wgs84 = true, export_bea_vertices = true,
          keep_intermediate = true, simplify_tolerance_m = 0
[run]     log_level = INFO, overwrite = false
Unknown keys or wrong types are rejected with a clear error.


6. TEST AND VALIDATION RESULTS
------------------------------------------------------------------------------------
pytest: 11 passed (config defaults == config.toml, override parsing/validation, cost
functions, routing around a wall, statuses on_road/no_path/origin_impassable, snapping,
adaptive buffer, multi-source cheapest road, full example end to end, BEA vertex export,
inputs untouched / re-run refused).

Example (Upington ROI, default settings): 222 origins (same as the original), 218 ok,
2 on_road, 2 origin_impassable (inside water with no passable cell within 100 m),
0 edge_limited, 7 origins snapped out of obstacles. Total run ~6 s.
Compared with the committed 2021 routes for the same origins: start points match (median
11 m), 52% end at the same road point (within 100 m); new routes are shorter (median
ratio 0.84) because flat ground is no longer free and the grid is isotropic.


7. KNOWN LIMITATIONS / FUTURE WORK (not done in this upgrade)
------------------------------------------------------------------------------------
- Physics extensions from the review documents (graded slope penalties, land-cover traction,
  switchback penalties, river crossings, seasonality) are not implemented; the cost function
  is isolated in surface.cost_from_slope() so they can be added there.
- The BEA proximity rasters (NGI/VR 100 m proximity) are not generated by this model yet.
- National scale: tiling keeps memory bounded, but the DEM is still warped in one piece;
  for all of South Africa warp per tile or use a VRT.
- The legacy/ scripts are kept unchanged for reference and do not run on current libraries.
- gdal-data/ and the committed outputs/, temp/, output_paths/ folders are no longer used by
  the code and can be deleted when you are happy with version 2.
